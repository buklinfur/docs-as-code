# Требования

## User Stories

### US-01. Вопрос по материалам

**Как** студент,  
**я хочу** задать вопрос обычным языком и получить ответ по учебным материалам,  
**чтобы** быстро найти нужную информацию, не перечитывая весь конспект.

Критерии приёмки:

- система принимает вопрос в виде текста длиной до 500 символов;
- ответ отображается не позднее чем через 10 секунд после отправки вопроса; если за это время ответ не получен, система прекращает ожидание, показывает сообщение «Не удалось получить ответ. Повторите запрос позже» и оставляет текст вопроса в поле ввода для повторной отправки;
- если в материалах нет подходящей информации, система сообщает об этом и не формирует ответ.

### US-02. Просмотр источников ответа

**Как** студент,  
**я хочу** видеть, на каких фрагментах материалов основан ответ,  
**чтобы** проверить его достоверность.

Критерии приёмки:

- под ответом отображается от 1 до 3 источников: название материала и номер страницы или раздела;
- при выборе источника показывается текст исходного фрагмента;
- источники упорядочены от наиболее релевантного к наименее релевантному.

### US-03. Загрузка учебных материалов

**Как** преподаватель,  
**я хочу** загрузить учебные материалы в систему,  
**чтобы** студенты получали ответы по актуальным лекциям.

Критерии приёмки:

- система принимает файлы форматов PDF, Markdown и TXT размером до 20 МБ;
- после загрузки материал получает статус «Проиндексирован», и по нему можно задавать вопросы;
- при загрузке файла неподдерживаемого формата или слишком большого размера отображается сообщение об ошибке с указанием причины.

## Use Case

### UC-01. Ответ на вопрос по материалам

**Актор**: студент

**Цель**: получить ответ на учебный вопрос на основе загруженных материалов, с указанием источников.

**Предусловие**: преподаватель загрузил материалы, они проиндексированы; студент открыл страницу с чатом.

**Основной сценарий:**

1. Студент вводит вопрос и нажимает «Спросить».
2. Система передаёт текст вопроса модели эмбеддингов и получает вектор вопроса.
3. Система ищет в векторном индексе три наиболее похожих фрагмента материалов.
4. Система передаёт вопрос и найденные фрагменты языковой модели (LLM).
5. LLM формирует ответ только на основе переданных фрагментов.
6. Система показывает студенту ответ и список источников.

**Альтернативный сценарий:**

- **3a.** Подходящие фрагменты не найдены (сходство ниже порога). Система сообщает «В материалах ответа не найдено» и предлагает переформулировать вопрос. Сценарий завершается.
- **4a.** Языковая модель не отвечает (ошибка или ответ не получен за 10 секунд). Система прекращает ожидание, показывает сообщение «Не удалось получить ответ. Повторите запрос позже» и оставляет текст вопроса в поле ввода. Сценарий завершается.

**Результат**: студент получил ответ с источниками либо понятное сообщение о том, почему ответа нет.
